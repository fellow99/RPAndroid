# overall-spec.md — 系统整体规格

> 状态：000-scaffold（描述目标系统的完整规格；实现按里程碑推进）。
> 语言：RFC 2119（MUST / SHOULD / MAY）。

## 1. 系统目的与用户

ManagedFloatingApp 让"被托管 App"运行在应用自有的虚拟屏上，并把**读取/操作该 App**的能力开放给：用户本人（三种呈现模式）与下游（REST / MCP / JS 自动化脚本）。目标是作为可配置、可调度、可自动化脚本化的 App 托管与自动化控制平台。

目标用户/调用方：
- 用户本人（通过配置界面与呈现模式直接操作被托管 App）。
- 智能体 / LLM（经 MCP server 调用工具）。
- 外部系统（经 REST API 集成 + 视频流查看）。

## 2. 核心能力（用户故事）

### 2.1 托管与操控 App
- 作为用户/外部调用方，我可以 **选择系统已安装 App** 并把它加载到自有会话（虚拟屏）。
- 我可以 **点击 / 滑动 / 长按 / 输入 / 按键 / 返回 / 启动 / 切换** 被托管 App。
- 我可以 **读取被托管 App 的界面**（控件树/元素列表）以了解当前状态。

### 2.2 画面输出
- 我可以获得被托管 App 的 **单帧截图**。
- 我可以获得其实时画面：**一期 MJPEG-over-HTTP**，二期 WebRTC（低延迟双向）。

### 2.3 呈现模式
- 我可以选择以 **浮窗 / 常规布局 / headless** 三种模式观看或操作同一会话，模式切换不中断正在运行的任务。

### 2.4 自动化服务任务调度
- 我可以配置 **自动化服务任务**（目标 App、自动化脚本、是否启用、执行时间）。
- 执行方式支持 **立即 / 间隔 / cron**。
- 任务由 **前台 Service** 承载，自动化脚本用 **JS 编写**，通过宿主能力操作被托管 App。

### 2.5 对外协议
- 我可以让智能体经 **MCP（SSE / streamable HTTP）** 调用托管操作与任务调度。
- 我可以让外部系统经 **REST API** 调用。
- 我可以经 **局域网直连 / USB(adb reverse)** 接入，**无公网需求**。

## 3. 功能需求（按域）

### FR-A 托管基座（core:shell）
- FR-A-001：系统 MUST 能创建一块自有虚拟屏并承载目标 App。
- FR-A-002：系统 MUST 能向虚拟屏注入输入（点击/滑动/按键）。
- FR-A-003：系统 MUST 能把虚拟屏帧提供给上层读取。
- FR-A-004：系统 MUST 支持免 root（无线调试配对）与可选 root 两条启动路径。
- FR-A-005：系统 SHOULD 在 Android 14+ 提供完整焦点/方向处理，低版本降级。

### FR-B 操作入口（core:controller）
- FR-B-001：系统 MUST 提供"读"能力：单帧截图、视频帧源、界面元素列表（经无障碍）。
- FR-B-002：系统 MUST 提供"写"能力：点击/滑动/长按/输入/按键/返回/启动/切换。
- FR-B-003：系统 MUST 作为用户触摸、REST、MCP、自动化脚本共用的唯一写入口（一致性）。

### FR-C 呈现（app）
- FR-C-001：系统 MUST 支持浮窗 / 常规布局 / headless 三种呈现模式。
- FR-C-002：系统 MUST 支持模式间切换且不中断运行任务。
- FR-C-003：用户触摸呈现画面时，系统 MUST 将触摸换算成虚拟屏坐标并回写。

### FR-D 对外接口（core:server）
- FR-D-001：系统 MUST 提供 REST API（列 App / 启动 / 点击 / 滑动 / 截图 / 读 UI / 任务）。
- FR-D-002：系统 MUST 提供 MCP server（SSE 或 streamable HTTP），封装操作与调度为 agent 工具。
- FR-D-003：系统 MUST 提供实时画面：一期 MJPEG-over-HTTP，二期 MAY 增加 WebRTC。
- FR-D-004：系统 MUST 绑定本机端口，支持局域网直连与 USB adb reverse。

### FR-E 自动化服务任务（core:script）
- FR-E-001：系统 MUST 提供执行 JS 自动化脚本的 **前台 Service**。
- FR-E-002：系统 MUST 支持 立即 / 间隔 / cron 三种执行方式。
- FR-E-003：系统 MUST 提供宿主能力供自动化脚本操作被托管 App（host.invoke）。
- FR-E-004：系统 MUST 将 JS 执行器部署在独立 `:node` 进程（崩溃隔离 + 可重启）。

### FR-F 配置界面（app）
- FR-F-001：系统 MUST 提供 UI 选择被托管 App、配置任务、开关、执行时间与自动化脚本。
- FR-F-002：系统 MUST 提供状态与日志查看。

## 4. 非功能需求

- **NFR-1 性能**：截图与观看应低延迟；MJPEG 满足局域网实时；WebRTC（二期）进一步降延迟。
- **NFR-2 兼容**：minSdk 24 可安装；托管能力按版本门控，低版本优雅降级。
- **NFR-3 稳定**：自动化脚本崩溃不拖垮整个应用（`:node` 进程）；调度可重启。
- **NFR-4 安全**：不落盘凭证；端服务鉴权（后续）。
- **NFR-5 可维护**：模块单一职责、单向依赖、规范文档为真相。

## 5. 系统边界

- **范围内**：App 托管与操控、画面输出、呈现模式、自动化脚本调度、REST/MCP 对外接口。
- **范围外**：AI 聊天/推理主循环（不做）；静音/多任务交接（不做）；公网/跨网穿透（不做）。
