# 009-mcp-tools Specification — MCP 工具完善

> Module: 009-mcp-tools
> Status: Implemented（as-built，2026-11-09）
> 需求来源：以 4 条真实用例（计算器 / 天气 / 日历 / 自动化任务）驱动 MCP 能力验证与补全
> 关联：`004-server`（对外接口）、`002-controller`（操作入口）、`005-script`（自动化服务任务）
> 说明：本文档为**回溯规格**，描述已实现的行为；不包含框架/文件路径等实现细节。

## 1. Module Overview

### 1.1 Purpose

让外部智能体仅通过 MCP 工具就能完成“看画面 → 点击 → 输入 → 调度任务 → 观察结果”的闭环，
而不是只能点按和截屏。模块以真实任务为验收口径，补齐“输入类、状态类、任务控制类、诊断类”能力。

### 1.2 Problems Solved

此前 12 个工具只能完成“列应用 / 启动 / 截图 / 点击 / 滑动 / 简单任务增删执行”，实测暴露四类断点：

1. **无法输入**：没有按键与文本注入，中文搜索、表单填写、返回/提交/删除都做不了。
2. **无法观察**：没有会话/屏幕状态查询，坐标只能靠猜；任务执行结果、脚本日志不可见。
3. **无法收口**：任务只能立即执行，不能停止、不能等待结果、不能按 id 查询单个任务。
4. **定时不可靠**：定时触发不计入运行统计/运行态；停用任务仍会排闹钟；停止信号会污染下一次执行；
   部分 ROM 回收精确闹钟权限导致息屏时定时任务不触发；重启/覆盖安装后闹钟丢失。

### 1.3 Scope

包含：
- 屏幕输入扩展：按键注入（返回/主页/回车/删除/粘贴等）、文本输入（含中文）。
- 状态与观察：会话/承载/虚拟屏分辨率/运行中任务/无障碍状态；统一日志读取与清理。
- 任务控制：单任务查询、停止、执行并等待结果；脚本可查询屏幕信息。
- 调度正确性：秒级 cron、运行统计与运行态、停用语义、停止信号生命周期、精确闹钟、重启恢复。
- 对外契约同步：MCP 工具文档、REST 文档、脚本接口文档。

不包含（明确排除）：
- 聊天/AI 主循环、智能体编排。
- 元素级 UI 自动化（无障碍树在虚拟屏上不可用的 ROM 限制，未绕过）。
- 新增输入法（不改变用户默认输入法）。
- 多显示器/多会话并行（仍为单会话单运行态）。

## 2. User Stories

- 作为外部智能体，我可以在被托管界面里**按返回/回车/删除**，以便完成导航与提交。
- 作为外部智能体，我可以向焦点输入框**写入中文文本**，以便搜索城市、填写标题。
- 作为外部智能体，我可以**读取会话与虚拟屏状态**，以便按真实分辨率计算点击坐标。
- 作为外部智能体，我可以**停止**正在运行或已排期的自动化任务，避免失控。
- 作为外部智能体，我可以**等待任务结束并拿到结果**，以便判断脚本成败。
- 作为外部智能体，我可以**读取脚本日志**，以便定位脚本失败原因。
- 作为外部智能体，我可以让任务**每分钟第 00 秒**触发，并在设备息屏、重启后仍然生效。
- 作为运维者，我可以看到任务**运行次数与最后状态**，以便判断调度是否在工作。

## 3. Functional Requirements

### 3.1 屏幕输入（Input）

- **FR-009-001**：系统 MUST 支持向被托管屏注入按键，接受原始键码或常用键名（返回、主页、回车、删除、粘贴、Tab、Esc、空格、方向键、音量、电源、菜单、搜索等）。
- **FR-009-002**：系统 MUST 支持向当前焦点输入框写入文本；对非 ASCII（中文等）MUST 同样可用。
- **FR-009-003**：文本注入 MUST 不要求用户切换或安装输入法，且失败时 MUST 返回失败而非崩溃。
- **FR-009-004**：按键/文本注入 MUST 与会话状态解耦：无会话时返回明确错误。

### 3.2 状态与观察（Observability）

- **FR-009-010**：系统 MUST 提供会话状态查询，至少包含：会话是否就绪、当前承载应用、虚拟屏宽/高/DPI、运行中任务 id、无障碍是否启用。
- **FR-009-011**：状态中的分辨率 MUST 与当前虚拟屏一致，作为坐标计算的唯一权威口径。
- **FR-009-012**：系统 MUST 提供统一日志读取（可按级别过滤、限制条数、清空），且**脚本日志 MUST 可见**。
- **FR-009-013**：系统 MUST 支持关闭当前承载应用而保留会话（回到应用列表）。

### 3.3 任务控制（Task Control）

- **FR-009-020**：系统 MUST 支持按 id 查询单个任务，返回含运行统计（最后运行时间、下次计划、运行次数、最后状态）。
- **FR-009-021**：系统 MUST 支持停止任务：取消已排闹钟、尽力中止正在执行的脚本、立即释放运行态，并把最后状态标为“已取消”。
- **FR-009-022**：系统 MUST 支持“立即执行并等待”：调用方可指定等待上限，返回是否结束及任务最新状态。
- **FR-009-023**：同一时刻 MUST 最多只有一个任务处于执行态；忙时新的执行请求 MUST 被拒绝并返回明确结果。
- **FR-009-024**：任务脚本 MUST 能读取当前屏幕信息（宽/高/DPI/承载应用/运行中任务），以便自适应坐标。

### 3.4 调度语义（Scheduling）

- **FR-009-030**：cron MUST 支持 5 字段（分 时 日 月 周）与 6 字段（秒 分 时 日 月 周）；“每分钟第 00 秒” MUST 可表达。
- **FR-009-031**：仅 5 或 6 字段合法，其它字段数 MUST 返回解析失败。
- **FR-009-032**：定时触发 MUST 计入运行次数与最后运行时间，MUST 暴露运行中状态，MUST 回写最后状态。
- **FR-009-033**：停用任务 MUST 不排下一次闹钟，且下次计划时间 MUST 归零。
- **FR-009-034**：每次执行开始前 MUST 清除遗留停止信号，避免上次“停止”误杀本次执行。
- **FR-009-035**：调度 MUST 使用精确闹钟能力；设备息屏时定时任务 SHOULD 仍按时触发。
- **FR-009-036**：设备重启或应用覆盖安装后 MUST 自动重排已启用任务的闹钟。

### 3.5 契约与文档（Contracts）

- **FR-009-040**：新增能力 MUST 在 MCP 工具清单（`tools/list`）与脚本接口文档中同步可见。
- **FR-009-041**：REST 与 MCP MUST 共用同一底层操作入口，行为一致（文本输入、按键、状态口径）。
- **FR-009-042**：文档 MUST NOT 落盘真实地址/凭据（统一占位符）。

## 4. Key Entities

| 实体 | 说明 | 关键属性 |
|---|---|---|
| 工具（Tool） | 对外能力单元 | 名称、描述、入参 schema、返回文本、错误标记 |
| 会话（Session） | 被托管 App 的虚拟屏承载 | 就绪、分辨率、DPI、承载应用 |
| 任务（Task） | 一段可调度的脚本 | id、名称、目标应用、脚本、启用、调度方式、cron/间隔、运行统计 |
| 运行态（Run State） | 全局唯一的“正在执行”标记 | 任务 id、开始时间、完成/取消 |
| 停止信号 | 请求中止当前脚本的标记 | 任务 id、存在与否 |
| 日志条目 | 统一日志 | 时间、级别、标签、内容 |

## 5. Acceptance Scenarios

### 场景 A：计算器求值（输入 + 视觉校验）

- Given 会话就绪
- When 承载计算器并输入 `1+2*3-4/55` 后求值
- Then 界面显示 `6.9272727…`

### 场景 B：天气搜索（中文输入）

- Given 会话就绪
- When 承载天气，打开城市管理，聚焦搜索框并写入「北京」
- Then 搜索结果出现「北京市 - 中国」；进入后显示北京市多日预报

### 场景 C：日历倒数日（中文 + 表单 + 提醒/闹钟）

- Given 会话就绪
- When 在日历创建「倒数日」：内容「元旦到了」、日期 2027-01-01、提醒「提前 3 天 20:00」、闹钟开启并保存
- Then 日历显示「元旦到了 · 53 天后」，详情显示「已开启闹钟提醒」

### 场景 D：定时连续按键（cron + 脚本 + 停止）

- Given 会话就绪且存在任务「测试连续按键」（目标计算器，cron 每分钟第 00 秒）
- When 脚本先按 `C`，再以 30ms 间隔点击 `1` 共 10 次
- Then 计算器显示 `1111111111`；运行次数增加、最后状态为成功、运行中状态可观察
- When 执行期间请求停止
- Then 脚本在下一个操作前中止，最后状态为「已取消」，后续执行不受上次停止影响

### 场景 E：状态与诊断

- Given 会话就绪
- When 读取状态
- Then 返回分辨率（如 1600×2560）、承载应用、运行中任务、无障碍状态
- When 任务执行并写脚本日志
- Then 统一日志可按 `Script` 标签检索到开始/结束记录

## 6. Non-Functional Requirements

- **兼容**：既有工具、REST 路径与 5 字段 cron 行为保持不变。
- **健壮**：无会话、参数缺失、脚本异常、服务启动失败等路径 MUST 返回明确错误，不得崩溃。
- **安全**：不新增公网暴露；日志不记录文本正文（只记长度/状态）；文档不含真实地址与凭据。
- **性能**：状态查询与日志读取为常量级；任务执行等待由调用方指定上限。
- **可诊断**：每个任务执行有开始/结束日志；定时链路异常可见。
- **国际化**：界面文案中文；工具描述英文（面向通用客户端）。

## 7. Assumptions & Constraints

- 目标设备为 Android 13 级 ROM；部分 ROM 会回收精确闹钟权限，需在安装时声明专用权限。
- 虚拟屏 UI 树在部分 ROM 不可读，元素级寻址不可依赖，需以截图 + 视觉定位为主。
- 非 ASCII 输入依赖系统剪贴板 + 粘贴键；会覆盖用户剪贴板，后台无法可靠恢复。
- 停止是“尽力而为”：同步长任务无法硬中断，只在下一次操作前生效。
- 运行态为进程内状态，进程被杀后由调度重建。

## 8. Dependencies

- 上游：托管会话（虚拟屏/注入）、操作入口（统一读写）、自动化服务（脚本执行/调度）、对外服务（传输与鉴权）。
- 下游：外部 MCP 客户端、播控页面（REST）、应用内自动化界面。
- 平台：精确闹钟、剪贴板、前台服务、开机广播。

## 9. 已知限制

- 剪贴板注入会覆盖用户剪贴板（记录于评审报告，未修复）。
- 脚本永久挂起时运行态不会自动超时释放（需显式停止）。
- 定时执行会重新计算所有间隔任务的起点（与当前里程碑语义一致）。
- 虚拟屏 UI 树不可读（ROM 限制），保持既有降级策略。
