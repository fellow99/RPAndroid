# ManagedFloatingApp 工程规划

> 现状：本仓库为空（greenfield）。参考工程：Mika（`d:\GitHub\AI\Mika`）的"后台屏 + 操作 App"实现。
> 本文档是 brainstorm 讨论结果的落盘，作为后续详细设计（spec）与实现计划（plan）的依据。

## 1. 背景与目标

做一个 Android 上的 **App 托管与自动化控制服务**：把系统里一个被托管的 App 加载到一块自有虚拟屏上，
由"用户本人"或"下游智能体/外部系统"读取其画面/界面并操作它（点击、滑动、输入等），
并可按照配置（立即 / 间隔 / cron）执行 JS 自动化脚本。

**明确不做**：Mika 式的 AI 聊天界面、AI 主循环、静音/多任务交接等高级能力。

## 2. 需求范围

### 2.1 面向被托管 App
- 能加载（启动/切换）系统里已安装的 App 到自有虚拟屏。
- 能操作：点击、滑动、长按、输入、按键、返回等。
- 能输出**截图**。
- 能输出**实时视频流**（一期 MJPEG-over-HTTP；二期 WebRTC）。
- 能读界面：无障碍控件树 / 元素列表（供下游与脚本读取当前屏幕状态）。

### 2.2 面向下游（外部智能体 / 系统）
- **MCP server**（SSE / streamable HTTP）：把操作与调度包装成 agent 工具。
- **REST API**：列 App / 启动 / 点击 / 滑动 / 截图 / 读 UI / 任务调度等。
- **实时视频流**：一期 MJPEG-over-HTTP，二期 WebRTC。

### 2.3 应用自身（配置 / 调度 / 呈现）
- **配置界面**：选打开哪个 App、配置任务、开关、执行时间、脚本管理、状态/日志查看。
- **呈现模式**（可切换）：浮窗渲染 / 常规布局 / headless。
- **脚本任务调度**：立即执行、间隔执行、cron 执行；执行 **JS 脚本**（引入
  `d:\node-bridge-workspace\aosp-node-runtime\` 的 Node 引擎）；**脚本执行器做成 service**。

## 3. 关键决策（已确认）

| 主题 | 决策 |
|---|---|
| AI 聊天 UI | 不做 |
| 网络模型 | 局域网 Wi-Fi 为主（电脑/agent 直连手机本地端口）；USB(adb reverse) 兼容开发；**无公网/跨网**需求 |
| 托管方式 | 免 root：无线调试配对 + 内置 shell 助手（Mika 路线）；root 作为可选加速 |
| 会话模型 | 单一"被托管 App 会话" = 一块虚拟屏；三种呈现方式共用同一会话与控制器 |
| 呈现模式 | 浮窗 / 常规布局 / headless 三模式可切换 |
| 视频流 | 一期 **MJPEG-over-HTTP**，二期 **WebRTC**（`org.webrtc:google-webrtc`） |
| 脚本执行器 | 做成 **前台 Service**；Node 跑在独立 `:node` 进程（崩溃隔离 + 可重启）；开发期先同进程跑通 |
| JS 运行时 | `io.github.fellow99:node-bridge:0.2.0` + `runtimeOnly io.github.fellow99:node-runtime:26.13.0` |
| minSdk / ABI | minSdk 24（Node 硬要求）；仅 **arm64-v8a** |
| 托管能力版本门控 | <12 降级、12–13 提示抢焦点、14+ 完整（焦点/方向/转屏冻结） |

## 5. 架构总览

```
┌────────────── ManagedFloatingApp (Android, arm64) ──────────────┐
│                                                                │
│  A. Shell 助手进程 (shell UID, 无线调试配对 / root 启动)         │
│     - VirtualDisplay 虚拟屏 + 启动/挪入目标 App                  │
│     - 输入注入 (tap/swipe/key/IWindowManager)                   │
│     - 方向 / 焦点处理 (14+ 完整)                                │
│        │ ImageReader 帧(Surface 跨进程给 app) + 控制/注入        │
│  B. ScreenController (主进程, 唯一操作入口)                      │
│     - 读: 截帧→PNG/JPEG / 视频编码; 无障碍控件树→元素列表        │
│     - 写: 点击/滑动/长按/输入/按键/返回/启动/切换                │
│  C. 呈现模式管理器 (浮窗 / 常规 / headless)                      │
│     - 同一帧 → SurfaceView / 流; 触摸→坐标换算→注入虚拟屏        │
│  D. 对外接口 (复用 ScreenController)                             │
│     - REST API (Ktor) / MCP server (SSE) / 视频流(MJPEG v1)     │
│  E. 脚本任务系统                                                 │
│     - ScriptExecutorService (前台) + 调度(立即/间隔/cron)        │
│     - JS 执行器: NodeRuntime 于独立 :node 进程                    │
│       · rt.host.register(...) 代理 → 主进程 ScreenController     │
│       · JS: await host.invoke('screen.tap', {x,y})              │
│  F. 配置界面 (选App/任务/开关/时间/脚本/状态日志)                 │
└─────────────────────────────────────────────────────────────────┘
```

## 6. 模块详述

### A. Shell 助手层
- 无线调试配对一次（6 位码，本机完成；root 时走 `su` 直连）。
- 内置 shell 助手进程（shell UID）：建虚拟屏、启动/挪入 App、注入输入。
- 与主进程经 Binder 通信；帧经 app 侧 `ImageReader` 的 Surface 直接接收（跨进程但不逐帧传）。

### B. ScreenController
- 唯一操作入口，REST / MCP / 脚本 / 用户触摸全部收敛到此。
- 读：单帧截图（PNG/JPEG）、MJPEG 帧源、控件树/元素。
- 写：事件注入（点击/滑动/长按/输入/按键/返回/启动/切换）。
- 呈现模式只负责渲染同一帧；触摸经坐标换算回写屏幕。

### C. 呈现模式管理器
- 浮窗：`SYSTEM_ALERT_WINDOW` + 可拖动 SurfaceView（用户可触摸操作）。
- 常规：App 内 Activity/SurfaceView 全屏或分屏承载。
- headless：不渲染，仅截帧 + 流 + 控制。
- 模式切换共用同一"被托管 App 会话"，不中断正在运行的任务/脚本。

### D. 对外接口
- 服务绑定 `localhost` 端口；USB 用 `adb reverse tcp:PORT tcp:PORT` 映射到电脑。
- REST：列 App / 启动 / 点击 / 滑动 / 截图 / 读 UI / 任务 CRUD / 状态。
- MCP (SSE / streamable HTTP)：将 ScreenController + 调度系统封装为工具集。
- 视频：一期 MJPEG-over-HTTP（每请求一帧或长连持续推帧）。

### E. 脚本任务系统
- **ScriptExecutorService**（前台 service）：任务编排与状态机。
  - 任务 = { 目标 App, 脚本, 是否启用, 执行方式(立即/间隔/cron) }。
  - 调度：`AlarmManager`(setExactAndAllowWhileIdle) 承担 cron/间隔唤醒；掌上调度承担"立即"。
- **JS 执行器**：Node 跑在独立 `:node` 进程（满足"一次启动 + 崩溃隔离 + 可重启"）。
  - 宿主能力 `rt.host.register('screen.xxx')` 经 Bound Service/AIDL 代理到主进程 ScreenController。
  - 脚本内 `await host.invoke('screen.tap', {x,y})` 操作被托管 App。
  - 崩溃后由 ScriptExecutorService 重启 Node 进程。
- 开发期先 Node 与主进程同构跑通，后续再切独立 `:node` 进程。

### F. 配置界面
- 应用首页：选择要托管的 App（列出已安装可启动项）。
- 任务页：新建/编辑任务（App、脚本、启用开关、执行时间）。
- 脚本管理：编辑/上传 JS 脚本。
- 状态/日志：当前调度、最近执行结果、运行日志、Node/shell 助手状态。

## 7. 版本适配策略（渐进增强）

- minSdk 24（安装与基础 UI / 配置可用）。
- 手机托管门控（运行时 `Build.VERSION.SDK_INT` + 能力探测，失败优雅降级，不崩溃）：
  - `>=14`：焦点/方向/转屏冻结完整能力。
  - `12–13`：可用，界面提示"后台屏可能短暂抢主屏焦点"。
  - `<=11`：降级——核心操作可用，但强制提示"此窗口会占据输入焦点"（或建议全屏操作）。
- 呈现模式在低版本可自动回退（如 headless / 全屏）。

## 8. 二期规划（暂不实现，仅记录）

- **WebRTC 真·低延迟双向视频**：引入 `org.webrtc:google-webrtc`，帧喂 VideoEncoder → WebRTC peer；
  局域网 ICE 直连（本需求无公网，基本无需 TURN）；可选反向下行输入通道。
- 与 MJPEG 并存（MJPEG 快、WebRTC 准）。

## 9. 技术栈 / 依赖草案

| 用途 | 选型 |

## 10. 里程碑 / 路线（建议）

1. **M1 最小可跑切片**：免 root 无线调试配对 + shell 助手建虚拟屏 + 启动一个 App + 截图 + 注入点击；headless + REST 最小集（`POC`，先验证对你设备走得通）。
2. **M2 呈现与操作**：浮窗 / 常规 / headless 三模式；触摸回写；完整 REST 操作 API。
3. **M3 脚本任务系统**：ScriptExecutorService + Node（`:node` 进程）+ 立即/间隔/cron 调度 + 配置界面。
4. **M4 对外协议**：MCP server (SSE)；MJPEG-over-HTTP 视频流；adb reverse 接入说明。
5. **M5 打磨**：状态/日志、错误恢复、低版本降级门控、文档。
