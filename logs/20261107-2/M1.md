# M1 进度记录（机制验证）

**设备**：192.168.0.100:42215（Android 16 / SDK 36 / arm64 / MIUI，免 root）

## M1-1 建虚拟屏 + 承载 App + 截帧 —— ✅ 已验证
- 免 root shell-UID `app_process` 助手（`tools/vdisplay/HelperMain.java`）创建 **可信虚拟屏**。
- 关键解法（Mika 同款）：
  - 公开 API `DisplayManager(shellCtx).createVirtualDisplay(...)`；
  - shellCtx = `createPackageContext("com.android.shell",0)`（uid 2000 匹配包名校验）；
  - 全套隐藏 flags `0x17dc9`（PUBLIC|OWN_CONTENT_ONLY|SUPPORTS_TOUCH|ROTATES_WITH_CONTENT|DESTROY_CONTENT_ON_REMOVAL|TRUSTED|OWN_DISPLAY_GROUP|ALWAYS_UNLOCKED|TOUCH_FEEDBACK_DISABLED|OWN_FOCUS|STEAL_TOP_FOCUS_DISABLED）；
  - 裁帧用 **ImageReader**（screencap -d 对虚拟屏不可靠）。
- `am start --display <id> -n com.android.settings/.Settings` 把 Settings 承载上屏。
- 截到 720×1560 的 Settings 虚屏帧（119247B 真实内容）。

证据：`mfa_vd_settings_before.png`（Settings 虚屏帧）。

## M1-3 输入注入 —— ✅ 已验证
- `input -d <displayId> tap/swipe/keyevent` 可精确命中虚拟屏上的 App：
  - `keyevent 4`(back) → Settings 被退出，虚屏变空白（62B 帧）；
  - `input -d <id> swipe` 滚动 → 帧内容变化（md5 fc37 ≠ 注入前 02e5）。
- 说明：`input -d` 返回无错误，注入确实作用到目标屏。

## M1-4 App 端 REST —— ✅ 已在 Android 16 目标设备验证
- App 内 Ktor(CIO) 服务器 + ScreenController；`/health`、`/apps` 在 `192.168.0.100:38053`（Android 16）跑通（pid 20907；13 个可启动应用）。
- 踩坑：```adb reverse``` 会占用设备端口导致 BindException；改用 ```adb forward tcp:8099 tcp:8099```。

## 关键结论
- 平台机制（建屏/承载/截帧/注入）在 Android 16 免 root 下**全部跑通** —— 剩余为应用侧集成与免 root 自举。
